# EXP เลเวล และแรงค์

`PlayerProgressionState` บน Player เป็นเจ้าของเลเวลและ EXP จริง เชื่อมกับ `PlayerProgressionUI` เดิม: ตัวเลขเลเวล แรงค์ และหลอดสีทองเหนือเลือด เริ่มเลเวล 1 สูงสุด 100

## กติกา

- ได้ EXP เมื่อผู้เล่นทำดาเมจสังหารมอนสเตอร์ ด้วยกระสุนหรือการโจมตีประชิด
- `EnemyHealth.TakeDamage(float, GameObject source)` ส่งรางวัลให้ `PlayerProgressionState` ของผู้โจมตีเฉพาะจังหวะตาย และเพียงครั้งเดียวต่อชีวิต
- ความเสียหายที่ไม่ตาย การตีซ้ำศพ และการตายที่ไม่มีผู้เล่นเป็นผู้ทำดาเมจสุดท้ายไม่ให้ EXP ส่วน CivilianHealth เป็นระบบแยก
- EXP ส่วนเกินทบไปเลเวลถัดไป รองรับการขึ้นหลายเลเวลจากรางวัลเดียว
- เลเวล 100 เก็บ EXP เป็น 0 และแสดงหลอดเต็ม ไม่เลื่อนเกินเพดาน

สูตร EXP สำหรับขึ้นจากเลเวล L ไป L+1:

`100 + 35 × (L − 1) + 12 × (L − 1)²`

ตัวอย่าง: เลเวล 1 ใช้ 100, เลเวล 10 ใช้ 1,387, เลเวล 50 ใช้ 30,627 และเลเวล 99 ใช้ 118,778 EXP รวมจากเลเวล 1 ถึง 100 ใช้ 4,002,273 EXP ปรับสมดุลได้ที่ `ExperienceForLevel`

แรงค์คำนวณจากเลเวลเสมอ ไม่ได้แยกเก็บเป็นข้อความที่อาจไม่ตรงกับเลเวล

## การบันทึกและต่อระบบ

- บันทึก JSON เวอร์ชัน 2 ใน PlayerPrefs key เดิม `TopDownShooter3D.Progression.v1` ประกอบด้วย version, level, experience และ upgrades 5 สาย; ยังโหลดเซฟเวอร์ชัน 1 ได้
- รวมการบันทึกเมื่อได้หลายรางวัลใกล้กันทุกประมาณ 0.75 วินาที และบันทึกทันทีเมื่อ pause/ปิด/ออกเกมหรือเปลี่ยนฉาก
- โหลดอัตโนมัติใน Awake ข้อมูลผิดช่วงหรือคนละเวอร์ชันจะไม่ทับสถานะปัจจุบัน
- `CaptureSave` / `RestoreSave` ใช้ต่อกับระบบเซฟรวมภายหลังได้; เลเวลที่เพิ่มให้แต้มอัปเกรดตาม [ระบบพัฒนาผู้เล่น](PLAYER_DEVELOPMENT_AND_GROUNDED_MOVEMENT.md)
- รางวัลใหม่ควรส่งแหล่งโจมตีผ่าน overload ที่มี source เพื่อให้ระบบระบุผู้สังหารได้

## การตรวจสอบ

`Logs/PlayerProgressionSetup.txt` ตรวจรางวัล prefab และบอสในฉาก

`Logs/PlayerProgressionPlaytest.txt` ตรวจขอบเขตแรงค์ เลเวล 100 EXP เกิน/ติดลบ/รางวัลขนาดใหญ่ การให้รางวัลครั้งเดียว กระสุนชนจริง จังหวะตีจากแอนิเมชันจริง HUD และเซฟ/โหลดใน player instance ใหม่ ใช้ key ทดสอบชั่วคราวแยกจากเซฟผู้เล่นและลบหลังจบ

รันทดสอบได้ที่ `Tools > Progression > Run EXP Combat Save and HUD Test`
